# Go 概念课写作规范

这是给写作者（包括 AI）的硬约束。目标：读完一篇只需 5–8 分钟，读者能自己推演结果，而不是记一堆 API。本课程是 Go 学习材料的**唯一主线**（19 篇），不设外部参考区；纯语法与 API 字典类内容不单独成章，**不要写成 API 手册**。

## 篇幅与节奏

- 单篇 **120–220 行**，不超过 250 行；不套"学习目标 / 小结 / 误区表 / 练习 / 下一篇"五段式模具。
- 每篇只解决一个核心问题；一个概念讲不透就拆成两篇，不在同一篇里顺手补齐相关 API。
- 语言顺序固定：**现象 → 直觉 → 机制 → 验证 → 边界**。
- 每小节至少回答一个"为什么"，而不是"是什么"。禁止连续两张属性表。
- 表格只用于"对照 / 决策"，不用于 API 字典。

## 章节骨架

```markdown
# NN · 标题（核心问题式，如"赋值到底复制了什么"）

> 一句话模型：……（全文唯一要背的句子）

## 先看一个现象
具体场景 + 最小 Go 片段 + "你以为……实际……"

## 先建立直觉
:::figure NN-slug|图题
图说明：图在讲什么，读者应该看出什么。
:::

## 机制拆成 N 步
### 1. ……
解释 + 必要代码 + "为什么"。
### 2. ……
……

## 动手验证
:::demo NN-slug|demo 标题
先预测：……（明确一个问题）
验证：怎么运行、改哪个参数、应该看到什么。
:::

## 容易误判的地方
- 误判 → 正确理解（2–3 条，不凑数）

## 自己再做一次
1. 任务 + **预期结果**（必须可核对）
2. ……

> 下一篇：[标题](NN-next.md)
```

## 图示规范

- 图必须是**真正的 SVG 文件**，存 `figures/NN-slug.svg`，禁止用 `text` 字符画冒充图。
- SVG 自带浅色背景（`#F7F8F4`）与深色文字，`viewBox` 用 `0 0 800 H`，不依赖外部字体或脚本。
- 一张图只表达一个关系：一条数据流、一棵决策树、一个内存剖面、一条状态链。塞不下就拆图。
- 图上文字用中文术语，与正文一致；箭头表示方向或优先级；颜色只区分"两类 / 两态"，不做装饰。
- 正文用 `:::figure 文件名|图题` 引用，构建脚本负责渲染。每篇 1–2 张图。

## Demo 规范

- Demo 是**真实可运行的 Go 项目**，放在 `examples/minimal/NN-slug/`，至少含 `main.go` 与 `go.mod`。
- `go.mod` 使用 `module example.com/go-course/NN-slug`、`go 1.24`；只用标准库，不依赖网络、真实数据库或凭据。
- 文件顶部放 1–2 个可调常量，并用注释 `// 可调参数` 标出；读者改它就能观察不同结果。
- 输出必须确定、可核对：用 `fmt.Printf` 打印关键数值、状态或前后对比，不用时间随机数制造不可复现结果。
- 不允许把 Demo 写成 Markdown 说明，也不要求浏览器执行 Go；离线站只内嵌源码与预测答案。
- Demo 必须能被 `gofmt -l` 检查、通过 `go vet ./...` 与 `go build ./...`；若包含测试，须通过 `go test ./...`。
- 正文用 `:::demo 文件名|标题` 引用，构建脚本负责内嵌源码与"揭晓"折叠块。

## 内容与准确性

- 面向"有些 Go 基础"的读者：默认已知变量、函数、结构体、`go run`，不解释 `var x int` 是什么。
- 术语首次出现给一句人话解释，再使用术语。
- 不写"某些情况可能不同"这类空话；要写就给具体条件与后果。
- 数值、输出、命令必须自洽：写了 `len=0, cap=2` 就不要在结论里悄悄换成别的数。
- API 只作为解释概念的工具，不能成为文章主体。

## 双形态交付

- Markdown 是源，必须能在普通 Markdown 预览器里读；`:::figure` / `:::demo` 在别的预览器里当作引用块也可接受。
- `course-site/index.html` 由 `python3 course-site/build_site.py` 从 Markdown 生成，图与源码内嵌，章节可切换，支持离线打开。
- 改了 Markdown、SVG 或 Demo 源码后，必须重新运行构建脚本。
